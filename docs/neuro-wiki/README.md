# Нейроны и коннектом: журнал утверждений

Это исследовательская wiki о клетках, группах и связях MaleCNS. Её предмет — **что известно о нейронной системе и что показала наша модель**. Результаты управления квадрокоптером остаются в [сводке экспериментов](../research-results.md); они не превращаются здесь в сведения о биологии мухи.

## Как устроен KAG

[claims.jsonl](claims.jsonl) — машиночитаемый граф утверждений: `subject → predicate → object`. Каждая строка имеет постоянный `id`, тип свидетельства, конкретный источник, область применимости и ограничение. Страницы ниже объясняют утверждения человеку и ссылаются на их `id`. Это минимальное представление KAG; поиска по графу, автоматического вывода и проверки новых связей пока нет.

Карту заметок начинайте с [[Карта нейронов]]. Ссылки вида `[[DNg02]]` и `[[SNpp37-38|SNpp37/38]]` образуют граф в Obsidian; для сохранения ссылок на отчёты в `runs/` откройте **корень репозитория** как хранилище. Линия между заметками показывает только перекрёстную ссылку. Направление и тип отношения задают текст и `claims.jsonl`.

| Тип свидетельства | Что разрешено утверждать |
| --- | --- |
| `published_experiment` | Только результат указанной публикации и её экспериментальных условий. |
| `dataset_annotation` | Тип, сторона или идентификатор клетки в указанной версии набора данных. Аннотация сама по себе не доказывает функцию. |
| `connectome_edge` | Направленная связь между **конкретными body ID** с числом синапсов, порогом и версией MaleCNS. Связь сама по себе не доказывает функциональный эффект. |
| `model_intervention` | Ответ фиксированной модели на конкретную стимуляцию, считывание и набор зерен. Это не физиологическое измерение. |
| `hypothesis` | Проверяемое предположение, не принимаемое за результат. |

Новый факт сначала оформляется как кандидат с точной ссылкой на фрагмент первоисточника или результат запуска. Перед добавлением в граф проверяются идентификаторы и версия данных, сторона, направление связи, знак и величина эффекта, условия стимула, контроль и граница вывода. Неоднозначный кандидат остаётся на странице как вопрос; отсутствие найденного пути не записывается как отсутствие биологической связи. Исправление старого утверждения сохраняет его `id` в истории Git и указывает заменяющее утверждение.

Для новой страницы используйте [шаблон](TEMPLATE.md). Исходный набор и его таблицы доступны на [официальной странице MaleCNS v1.0](https://male-cns.janelia.org/download/).

Для сверки с опубликованной анатомией и физиологией используйте [список первичных источников](Источники.md).

Правила пополнения для работающих с этой папкой агентов записаны в [AGENTS.md](AGENTS.md).

## Проверка перед сохранением

Установите [CUE CLI](https://cuelang.org/docs/introduction/installation/) (в CI закреплена версия `v0.17.1`) и выполните из корня репозитория:

```sh
python3 scripts/check_neuro_wiki.py
```

[CUE-схема](claims.cue) требует общие поля и дополнительные поля по типу свидетельства: у модельного ответа — релиз данных и исходный отчёт, у анатомического ребра — body ID, число синапсов, фильтр и запрос. Скрипт также проверяет уникальность `id`, локальные источники, ссылки и наличие страницы для каждого утверждения. Успешная проверка не подтверждает истинность числа или биологическую интерпретацию: их нужно сверять с первоисточником.

- [[H2]]: опубликованные записи направленного ответа у живой мухи как ориентир для проверки оптической карты; с нашим MaleCNS входом ещё не сопоставлены

Первый содержательный запрос к коннектому — выяснить, какие проверяемые пути связывают выбранные клетки `DNg02` с группой `DLM/DVM`. Для этого нужны body ID, версия **MaleCNS v1.0**, направленные рёбра, веса, порог и воспроизводимый запрос. Наличие модельного ответа `N-002` заранее не доказывает ни прямую связь, ни конкретного посредника. До такой проверки страницы описывают опубликованные функции и ответы модели, а не доказанный нейронный путь.
